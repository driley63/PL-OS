# Contributing

PL-OS accepts changes through a governed documentation workflow. Treat every edit as a product change, even when the change looks like copy.

## Contribution Types

- Editorial patch: grammar, spelling, formatting, or clarification without changing meaning.
- Specification change: a new requirement or changed standard.
- ADR proposal: a decision that should become permanent history.
- RFC proposal: an idea that requires review before it becomes a standard.
- Release change: version manifest, migration note, or changelog update.

## Workflow

1. Create or update an RFC when a change affects behavior, design, engineering, governance, or user expectations.
2. Convert an accepted RFC into an ADR when the decision is ready to be locked.
3. Update affected specifications and examples.
4. Add release notes and migration guidance when the change affects implementers.
5. Open a pull request using the repository PR template.

## Review Standard

A change is ready when it is clear, versioned, traceable, accessible, implementation-ready, and consistent with PL-OS Core.

## Language Standard

Use plain, direct language. Avoid marketing filler in specifications. Every requirement should be testable or reviewable.
