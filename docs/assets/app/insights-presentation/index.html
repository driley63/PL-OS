PL-OS review notes

Separate the finding, its supporting evidence, and the optional AI explanation. Today offers a brief entry point; Insights provides the inventory; a detail route provides the full context. This prototype proposes behavior and does not change the released app or PL-OS contract.

Finding types and visuals

Connection: paired values with labels and units, explicitly an association. Trend: compare matched periods only when a real baseline exists; otherwise show the current value alone. Goal progress: relate the finding to the selected goal, without a fabricated goal-completion percentage. Observation: a count or compact factual sentence. No decorative chart when it adds no information.

Information and evidence

Each finding needs a stable identity, type, topic, source, observation window, data timestamp, display template, supported metric values and units, evidence references, coverage, limitations, optional comparison, optional suggested action and report-level care context. These are proposed display requirements; today’s LocalFinding contract provides only part of them. Preserve on-device exclusions when entering AI chat.

Use plain source language such as “Found on your device.” AI Purple and “AI-assisted” identify the explanation only. “Possible connection” describes finding type, not measured confidence. Do not invent high/medium/low labels, percentages, paired-day counts or baseline values. Hide an unavailable comparison and state what is missing.

Ordering and freshness

Display care notices independently of ranking and dismissal. Rank eligible findings by newly changed evidence, relevance to the user’s goals and evidence adequacy, then use a stable tie-breaker. Record the evidence fingerprint separately from “opened” state. A repeat of unchanged evidence must not be marked new. Unchanged findings remain reachable; they do not repeatedly displace today’s logging.

Actions and accessibility

Open finding → details. View entries → timeline filtered to supporting records. Ask a follow-up → supported chat context with the user’s question editable. Plan action → preview and explicit start, never automatic enrollment. Save, dismiss and feedback are proposed controls; dismissing a finding cannot remove an applicable care notice.

Use semantic headings, 44-point minimum targets, keyboard operability, visible focus and announced expanded/selected states. Treat a short card heading as concise authored content rather than clipping essential qualifiers. Support large text without fixed card heights or horizontal scrolling. Charts require an equivalent text comparison. Dynamic Type, VoiceOver and native dark-mode validation remain acceptance work for the eventual app implementation.
